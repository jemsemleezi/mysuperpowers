# 改进代码库架构

揭示架构摩擦并提出 **深化机会**——将浅层模块重构为深层模块的改动。目标是可测试性和 AI 可导航性。

## 术语表

在每个建议中 **精确** 使用这些术语。一致的语言就是重点——不要滑向"component"、"service"、"API"或"boundary"。完整定义见 [LANGUAGE.md](LANGUAGE.md)。

- **Module（模块）** —— 任何具有接口和实现的东西（函数、类、包、切片）。
- **Interface（接口）** —— 调用者使用该模块必须知道的一切：类型、不变量、错误模式、排序、配置。不仅仅是类型签名。
- **Implementation（实现）** —— 内部的代码。
- **Depth（深度）** —— 接口处的杠杆率：大量行为藏在小接口后面。**深层** = 高杠杆。**浅层** = 接口几乎与实现一样复杂。
- **Seam（缝）** —— 接口所在的位置；可以在不原地编辑的情况下改变行为的地方。（用这个，而非"boundary"。）
- **Adapter（适配器）** —— 在缝处满足接口的具体事物。
- **Leverage（杠杆）** —— 调用者从深度中获得的东西。
- **Locality（局部性）** —— 维护者从深度中获得的东西：变更、Bug、知识集中在一个地方。

关键原则（完整列表见 [LANGUAGE.md](LANGUAGE.md)）：

- **删除测试**：想象删除该模块。如果复杂度消失了，它只是一个透传。如果复杂度在 N 个调用者中重新出现，说明它确实发挥了作用。
- **接口就是测试面。**
- **一个适配器 = 假想缝。两个适配器 = 真实缝。**

此技能 _受_ 项目的领域模型 _指导_。领域语言为好缝命名；ADR 记录技能不应重新争论的决策。

## 流程

### 1. 探索

首先阅读项目的领域词汇表以及你所涉及区域的任何 ADR。

然后使用 Agent 工具的 `subagent_type=Explore` 遍历代码库。不要遵循僵化的启发式规则——有机地探索并注意你在哪里遇到了摩擦：

- 理解一个概念需要在许多小模块之间来回跳转的地方在哪里？
- 哪些模块是 **浅层** 的——接口几乎与实现一样复杂？
- 哪些地方纯函数只是为了可测试性被提取出来，但真正的 Bug 隐藏在它们被调用的方式中（缺乏 **局部性**）？
- 哪些紧耦合的模块从它们的缝中泄漏？
- 代码库的哪些部分未被测试，或通过当前接口难以测试？

对你怀疑是浅层的任何东西应用 **删除测试**：删除它会使复杂度集中，还是只是转移？"是的，会集中"就是你要的信号。

### 2. 呈现候选

呈现一个编号的深化机会列表。对于每个候选：

- **文件** —— 涉及哪些文件 / 模块
- **问题** —— 为什么当前架构造成了摩擦
- **解决方案** —— 用通俗英语描述将改变什么
- **收益** —— 从局部性和杠杆率角度解释，也从测试如何改进的角度解释

**领域使用 CONTEXT.md 的词汇，架构使用 [LANGUAGE.md](LANGUAGE.md) 的词汇。** 如果 `CONTEXT.md` 定义了"Order"，就谈"Order 接收模块"——而非"FooBarHandler"，也非"Order service"。

**ADR 冲突**：如果候选与现有 ADR 矛盾，只有在摩擦真实到值得重新审视 ADR 时才提出它。清晰标记（例如 _"与 ADR-0007 矛盾——但值得重新讨论，因为…"_）。不要列出 ADR 禁止的每个理论重构。

**不要**在此时提出接口。询问用户："你想探索其中哪一个？"

### 3. 追问循环

一旦用户选择了候选，进入追问对话。与他们一起遍历设计树——约束、依赖、深化模块的形状、缝后面是什么、哪些测试能保留下来。

副作用在决策成型时内联发生：

- **以 `CONTEXT.md` 中不存在的概念命名深化模块？** 将该术语添加到 `CONTEXT.md`——与 `/grill-with-docs` 相同的纪律（见 [CONTEXT-FORMAT.md](../grill-with-docs/CONTEXT-FORMAT.md)）。如果文件不存在则惰性创建。
- **在对话中精炼了模糊术语？** 立即更新 `CONTEXT.md`。
- **用户以有说服力的理由拒绝了候选？** 提议一个 ADR，措辞为：_"你想让我把它记录为 ADR 吗，这样未来的架构审查不会再提出它？"_ 只有在理由确实对未来探索者有参考价值时才提议——跳过短暂原因（"目前不值得"）和不言自明的原因。见 [ADR-FORMAT.md](../grill-with-docs/ADR-FORMAT.md)。
- **想探索深化模块的替代接口？** 见 [INTERFACE-DESIGN.md](INTERFACE-DESIGN.md)。
